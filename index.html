High-Performance, Zero-Copy Layer 7 Admission Control for AI Inference Traffic

Custos stops malicious messages before they reach AI inference servers. It works by scanning incoming requests on the network connection and rejecting any that violate basic message rules. This happens before the AI system reserves memory or starts processing, keeping it fast and safe.

01 / Threat Model & Systems Boundaries

Application-Layer Protobuf Threat Taxonomy

Network firewalls cannot see inside encrypted messages. Many security tools break inference speed by deserializing entire messages. Custos works directly on the encrypted network stream and checks for six common attack patterns that cause crashes or slowdowns.

1. Protobuf Nesting & SGROUP Bombs Stack Exhaustion

An attacker sends messages with many levels of nesting (100s deep), or uses old message formats that parsers don't expect. Normal parsers have to track each level and run out of memory.

Runtime Impact: The AI server crashes trying to track all the nesting levels.

✓ Defense: Custos stops messages that nest deeper than 16 levels or use old formats, before the AI system sees them.

In plain English

Picture a parcel with a smaller parcel inside it, and a smaller one inside that — hundreds deep. Each time the server opens one, it has to jot down where it was so it can find its way back out. Open enough of them and it runs out of notepad and crashes.

Custos doesn't open the parcels. It just counts them, and the moment it hits number 17 (or sees a disguised legacy box) it throws the whole thing in the bin.

2. Tensor Shape Overflows OOM / Integer Wrap

An attacker sends requests that claim the data is extremely large (like declaring a picture is "negative one" pixels or "a billion by a billion" in size), or uses numbers so big they wrap around to become small numbers.

Runtime Impact: The AI server wastes memory trying to allocate space for data that doesn't really exist and crashes.

✓ Defense: Custos multiplies the claimed size numbers before allowing them. If the size is bad or too large, the request is rejected.

In plain English

Before sending a picture, the request announces how big it is. A liar can claim it's minus one pixels wide, or a billion by a billion. The server believes the label, immediately tries to clear a shelf that enormous, and gets killed for hogging memory.

Custos does the multiplication first. If the claimed size isn't a sensible number, the request never reaches the shelf.

3. Malformed Varints Parser CPU Hang

Numbers in messages are sent in chunks. An attacker sends a chunk that says "there's more" but never sends the next piece, or sends more than 10 chunks when 10 is the limit.

Runtime Impact: The parser waits forever or runs forever trying to decode the number, freezing an entire AI server worker thread.

✓ Defense: Custos stops reading after 10 chunks and rejects the message if it's not complete by then.

In plain English

Big numbers get sent in small pieces, and every piece ends with "…and there's more coming". A troublemaker sends pieces that always say that and never finish the sentence. A naive reader waits forever, pinning a CPU core at 100%.

Custos knows a real number is never longer than 10 pieces, so it stops listening at the 11th and rejects the request.

4. Shape-to-Payload Parity Mismatch CVE-2025-23320

An attacker declares that a request contains a large image (like "a 224×224 pixel picture"), but only includes 64 bytes of data instead of the 2.4 million bytes that should be there.

Runtime Impact: The AI system tries to read data that isn't there, reading someone else's data from memory instead, or crashing with an illegal memory access.

✓ Defense: Custos checks that the declared size exactly matches the actual data size. If they don't match, the request is blocked immediately.

In plain English

Imagine ordering a 24-pack of soda (a perfectly reasonable size), but the delivery box only has one can inside. If the warehouse robot blindly grabs 24 cans' worth of space off the conveyor belt, it ends up grabbing 23 cans belonging to the customer behind you.

Custos checks that the weight of the box matches the label before letting it inside.

5. Shallow Unknown-Field AST Flood CVE-2021-22569

Instead of nesting messages deeply, an attacker sends thousands of unrecognized fields (each 2 bytes) all at the top level. The parser doesn't see them as threatening because there's no nesting, but it has to record every one.

Runtime Impact: The parser allocates huge amounts of memory trying to remember all these unknown fields, slowing or freezing the server.

✓ Defense: Custos stops reading after 1,024 fields total and rejects the message. It never stores unknown fields in memory.

In plain English

Instead of nesting boxes inside boxes, the attacker hands the clerk a single flat sheet covered in 10,000 tiny nonsense sticky notes. A dutiful clerk files a separate manila folder for every sticky note they don't recognize, quickly filling the entire filing room.

Custos never creates folders for unknown notes, and if a form has more than 1,024 fields total, it rejects it on the spot.

6. Shared-Memory & Model-Repo RPCs CVE-2024-0088

An attacker calls administrator functions (commands to load new models or access shared memory) that should only be available to staff, but are exposed on the same port as normal user requests.

Runtime Impact: The attacker can read or change AI model files, load malicious code, or access other customers' data.

✓ Defense: Custos has a list of allowed functions. Any call to admin functions is rejected immediately with an error.

In plain English

By default, Triton puts the customer service window (ModelInfer) and the staff-only control room door (RepositoryModelLoad, SystemSharedMemoryRegister) in the exact same hallway with no lock on the door.

Custos checks the door name on the envelope header before even looking inside — if you aren't asking for an inference or a health check, the door stays locked (`403 Forbidden`).
