# Custos-Web

**Minimalist Visual Guide, Interactive Wire Inspector, and Telemetry Dashboard for Custos**

Built with **no build step and no network dependencies** (semantic HTML5, modern CSS adhering strictly to the **Catppuccin Mocha & Latte** palette, and vanilla ES6 JavaScript) so it can be hosted directly on **GitHub Pages** or run locally in seconds.

The only third-party code is [Motion One](https://motion.dev) (~64 KB), **vendored locally** at [`vendor/motion.min.js`](./vendor/motion.min.js) rather than pulled from a CDN, so the site stays entirely self-contained and works offline. It powers the scroll reveals, staggered intros, and chart draw-on animations in [`motion-init.js`](./motion-init.js). That file is purely decorative and fully optional — if the library is blocked, fails to load, or the visitor has `prefers-reduced-motion: reduce` set, the page degrades to its static appearance with all content visible and all interactions intact.

## 1. What This Website Covers

1. **Application-Layer Threat Taxonomy (`#threat-taxonomy`):**
   Visualizes why L3/L4 firewalls, AST-deserializing L7 WAFs, and L2/L3 `AF_XDP` kernel-bypass filters fail for encrypted, HTTP/2-multiplexed KServe v2 inference traffic, and breaks down the six exploit families defended by Custos (each with an interactive **ELI5** plain-English overlay):
   * **Protobuf Nesting & `SGROUP` Bombs** (`Wire Type 2` recursion exceeding `MAX_DEPTH = 16` and `CVE-2024-7254` `Wire Type 3` `SGROUP` bypasses)
   * **Tensor Shape Overflows** (negative two's-complement varints, 64-bit integer wraparounds, and `>16.77M` element OOM dimensions)
   * **Malformed Varints** (`11+` continuation bytes, 10th-byte 64-bit overflows, and truncated EOFs)
   * **Shape-to-Payload Buffer Parity Mismatch (`CVE-2025-23320`)** ($\sum(\prod \text{dim}_i \times \text{sizeof}(\text{datatype})) \neq \text{len}(\text{raw\_input\_contents})$ causing cross-tenant memory leaks or `cudaErrorIllegalAddress`)
   * **Shallow Unknown-Field AST Flood (`CVE-2021-22569` / `CVE-2022-1941`)** (thousands of 2-byte unknown tags at `D = 0` exceeding `DEFAULT_MAX_TAGS_SCANNED = 1024`)
   * **Shared-Memory & Model-Repository RPC Hijacking (`CVE-2024-0088` / `CVE-2025-23329` / `CVE-2024-53880`)** (header-stage RPC allowlisting blocking `SystemSharedMemoryRegister`, `CudaSharedMemoryRegister`, and `RepositoryModelLoad` with `HTTP 403` / `gRPC PERMISSION_DENIED`)
2. **Interactive KServe v2 Byte-Level Wire Inspector (`#wire-inspector`):**
   Allows visitors to click through 9 representative payloads from [`Custos-Bench/corpus/`](../Custos-Bench/corpus/) (`benign_b1`, `nesting_depth_17`, `sgroup_wire_type_3_bomb`, `shape_neg_packed`, `shape_wrap_64bit_packed`, `shape_reordered_tail`, `shape_buffer_mismatch_underread`, `varint_unterminated_11`, and `unknown_field_ast_flood`) and inspect each hex TLV segment (`00 00 ...` gRPC header, Root Field 5 `inputs`, Inner Field 3 `shape`, and $O(1)$ cursor jumps over Root Field 7 `raw_input_contents`), displaying the exact `custos-core` `ParseError` and Envoy `ImmediateResponse` verdict.
3. **Production & Baseline Evaluation Architectures (`#topologies`):**
   Interactive architectural diagrams contrasting the three unified setups:
   * **Custos Production (Gateway + Sidecar)** — Envoy Ingress Gateway + `custos-proc` Native Sidecar sharing a RAM-backed Unix Domain Socket (`/var/run/custos/ext_proc.sock`, mode `0660`)
   * **Proxy Baseline (Envoy Only)** — Standard Envoy HTTP/2 proxy forwarding to Triton without `ext_proc`, isolating proxy overhead from Custos wire-inspection overhead
   * **Unprotected Control (Direct Triton)** — Direct gRPC to NVIDIA Triton Inference Server with zero L7 proxy or wire admission control
4. **System Performance & Survivability Dashboard (`#telemetry`):**
   Renders log-scale Coordinated-Omission Latency CDF curves (`P50`–`P99.99`), Achieved Goodput bar charts, and trial comparison tables across `steady-benign`, `interleaved` (`99%` benign / `1%` malicious), and `saturating-burst` (`2,000` concurrent attacks).
   * **Live Home Lab JSON Importer:** Click **`📂 Load custos-bench JSONs`** in the dashboard header and select any `results/**/*.json` trial files generated by [`Custos-Bench`](../Custos-Bench) to immediately plot and tabulate your live home lab benchmark runs in the browser.

## 2. Local Testing Instructions

Because `Custos-Web` is a static site with no build step, you can run and test it locally using Python's built-in HTTP server:

```bash
cd /Users/jpvalentine/Workspace/CUSTOS/Custos-Web
python3 -m http.server 8080
```

Then open **`http://localhost:8080`** in your browser.

### Testing Checklist
1. **Theme Toggle:** Click the **`🎨 Catppuccin Mocha`** button in the top-right navigation bar to switch between **Catppuccin Mocha** (dark) and **Catppuccin Latte** (light).
2. **Wire Inspector:** Click each payload on the left sidebar (`benign_b1`, `nesting_depth_17`, `shape_neg_packed`, etc.) and click individual colored hex byte blocks to verify byte-offset explanations.
3. **Architecture Switcher:** Toggle between **Custos Production (Gateway + Sidecar)**, **Proxy Baseline (Envoy Only)**, and **Unprotected Control (Direct Triton)**.
4. **Live JSON Import:** After running `custos-bench` on your home lab, click **`📂 Load custos-bench JSONs`** and select your exported `*.json` trial files from `Custos-Bench/results/` to verify live chart and table rendering. (You can also bake your final home lab numbers permanently into `REFERENCE_TRIALS` inside [`app.js`](./app.js)).
5. **Motion:** Confirm the ASCII `CUSTOS` wordmark cascades in on load, sections fade up as you scroll, the progress bar at the very top tracks scroll position, and the latency curves draw themselves in when the dashboard enters view.
6. **Reduced Motion:** Enable *Reduce Motion* in your OS accessibility settings and reload — every animation should be suppressed while all content stays fully visible.

## 3. Deploying with GitHub Pages (GitHub's Static Site / Blog Feature)

Yes — **GitHub Pages** is ideal for hosting `Custos-Web`. We have included a ready-to-use GitHub Actions workflow ([`.github/workflows/deploy-pages.yml`](./.github/workflows/deploy-pages.yml)) and a [`.nojekyll`](./.nojekyll) marker.

### Option A: Dedicated Repository (`Custos-Web` or `<username>.github.io`)
1. Initialize and push this directory to a GitHub repository:
   ```bash
   cd Custos-Web
   git init
   git add .
   git commit -m "Initial commit: Custos visual guide and benchmark dashboard"
   git branch -M main
   git remote add origin git@github.com:<your-username>/Custos-Web.git
   git push -u origin main
   ```
2. In your GitHub repository, navigate to **Settings → Pages**.
3. Under **Build and deployment → Source**, select **GitHub Actions** (or select **Deploy from a branch** → `main` / `/ (root)`).
4. Your site will automatically publish at `https://<your-username>.github.io/Custos-Web/`.

### Option B: Hosting Inside `Custos-Gateway` (`/docs` Folder)
If you prefer to host the website directly from your existing `Custos-Gateway` repository without creating a third repo:
1. Copy the contents of `Custos-Web/` into `Custos-Gateway/docs/`.
2. In `Custos-Gateway` on GitHub, go to **Settings → Pages**, choose **Deploy from a branch**, select `main` and `/docs`, and click **Save**.
